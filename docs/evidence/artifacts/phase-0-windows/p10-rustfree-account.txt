P0-10: exported player under a Rust-free local account
=======================================================

The check's wording is "a folder containing only the built player and hello-story runs
on a Windows machine with no Rust or Cargo INSTALLED". Windows Sandbox on this host is
unusable (see p10-sandbox-broken.txt), so the test was run under a freshly created local
account that has no Rust toolchain anywhere reachable.

Rust on this host is per-user only:
  machine (system) PATH cargo/rust/rustup hits : (none)
  HKLM uninstall entries for Rust             : none
  C:\Program Files\Rust                        : absent
  C:\Program Files (x86)\Rust                  : absent
  C:\Users\andre\.cargo\bin                    : present -- ONLY on andre's *user* PATH
  ACL on C:\Users\andre\.cargo                  : no grant to other users (deny by default)

Why no frame was captured from this account
-------------------------------------------
  Start-Process -Credential places the player in a separate logon session on a
  non-interactive window station. The window handles are enumerable from the operator's
  session (hwnd 1313212, 1296x759), but PrintWindow refuses them:

    PrintWindow FAILED (LastError=1400)   # ERROR_INVALID_WINDOW_HANDLE

  This is a Windows session-isolation boundary, not a player fault. A frame requires an
  interactive logon as weftora-p010 on the real desktop. The check's required evidence is
  "steps, machine description, log" -- all three are above.

Caveat
------
  This is a fresh *account*, not a separate *machine*: C:\Users\andre\.cargo still exists
  on the same disk. The isolation is real at the account boundary (no PATH entry, no
  profile directory, no ACL grant), but a reviewer can still object that the host is not
  literally Rust-free. Closing that needs either an interactive logon as weftora-p010 for
  a captured frame, or a genuinely separate VM.
